# Virtua Cop VR 0.1.3 development preview

0.1.2 improved speed but the user still reported slow motion and stretched audio. Its actual headset session fell to84.1% native speed. This candidate reduces the cost of the sound serial clock while retaining the native CPU frequencies, baud rate, audio synthesis and playback rate.

Both serial ports must be empty, waiting for a start bit with the line high, and in their supported asynchronous x16 mode before idle pulses can be combined. Divider maintenance and ready/IRQ notifications retain their original edge times. The first guest write is synchronized with earlier device events; every1us clock edge resumes on the original phase throughout active traffic. Reset invalidates queued writes from before the reset.

Two controlled45-native-second PC comparisons used24.2–26.0% fewer CPU cycles. All11gameplay images,5backupRAM captures,335decoded sound bytes and3360transmitted bits match. Each mode also reproduces all22state/image/audio files byte-for-byte across its repeated runs. The largest serial timestamp difference is0.16ms, with a median difference of0. Native sound commands, duration and sample format match; PCM samples differ between raw and idle scheduling. Frequency-band comparisons are recorded as diagnostic evidence, not physical listening acceptance.

The arithmetic and timer-queue experiments with no useful measured PC gain were removed. Settings, controls, native guns/HUD, infinite clouds and authored scene coverage retain their existing behavior.

Quest performance and physical audio/gameplay acceptance remain pending for this candidate. PCVR is software tested only. Native MAME debug quickstates can stall after reload in both the original0.1.2 raw engine and this candidate; they remain unsupported. Normal app settings and NVRAM persistence are separate and continue to be tested. The existing2of9neutral-raster comparisons below98% and finite native scene coverage remain documented limitations.
